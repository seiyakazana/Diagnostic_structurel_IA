- (decision) AD-1 Paradigm: local-first with server-authoritative reconciliation, ports-and-adapters inside each unit. Binds all. Prevents: half the units treating the server as the live read path and blocking the UI on network. Rule: on-device SQLite is the only read/write surface the UI touches; Postgres is the record of truth; no UI code path awaits a network call.
- (decision) AD-2 Single-writer ownership of a Releve. Binds CAP-1,2,4. Prevents: two devices editing one Releve and forcing merge/CRDT semantics nobody specified. Rule: a Releve has exactly one owning device-assignment at a time; a second Expert must take ownership before writing.
- (decision) AD-3 Binaries never travel in the sync stream. Binds CAP-3,4,5,11. Prevents: photo bytes bloating the sync stream and a row being unusable until its blob lands. Rule: photos/sketch rasters live in object storage via the attachment queue, content-addressed; the row is valid and syncable before its blob resolves; every consumer handles blob-pending.
- (decision) AD-4 Identity is a client-minted UUIDv7 assigned offline; the human-visible desordre number is DERIVED at render time, never stored. Binds CAP-2,5,6,8, FR-15, acceptance 9.1.e. Prevents: two offline devices minting desordre number 7, and numbering drifting between Releve, Coupe and Fiche. Rule: one ordering function computes display numbers from (zone order, element order, capture timestamp, id) and every surface calls it.
- (decision) AD-5 One report renderer, one document model. Binds CAP-5, FR-17/18/19, acceptance 9.1.d/9.1.f. Prevents: an on-device renderer and a server renderer producing two different compliant-ish layouts. Rule: rendering consumes a versioned RapportDocument value; the renderer is a single pure-Dart library compiled into BOTH the app and the server; no surface hand-builds PDF primitives.
- (decision) AD-6 Coupes and Schemas persist as vector documents with normalized-coordinate anchors, never as rasters. Binds CAP-6,7,8. Prevents: a raster captured at phone DPI going illegible in the PDF, and desordre positions becoming unrecoverable/uneditable. Rule: geometry is SVG-subset + anchors in 0..1 space resolved against the coupe viewbox; rasterization happens only inside the renderer.
- (decision) AD-7 AI output is an additive record class that never mutates Releve rows; Validation is an append-only event. Binds CAP-9,10,11,12,14, FR-13/14/21. Prevents: a correction overwriting the model proposal and destroying the training signal, and unclear provenance in a signed deliverable. Rule: Detection and Validation are separate rows; corrections write a new Validation event carrying expert, timestamp, mission, ouvrage; nothing is updated in place.
- (decision) AD-8 The PDF assembly gate is enforced in the document-model build, not in the UI. Binds CAP-5,10,14, FR-13/17. Prevents: a second surface (back-office, batch export, future API) shipping unvalidated AI text into a signed Rapport because only the mobile screen enforced it. Rule: RapportDocument construction rejects any Detection or drafted text lacking a terminal Validation event; the UI gate is a convenience, not the enforcement point.
- (decision) AD-9 Every model inference is an asynchronous job; no surface calls a model synchronously. Binds CAP-9,14, FR-11/12. Prevents: the CV path and the LLM path being wired differently, and a UI thread blocking on inference. Rule: one job contract (submit, poll/subscribe, terminal state) fronts both paths; results arrive as AD-7 Detection rows.
- (decision) AD-10 The LLM provider sits behind a port with no provider types crossing it. Binds CAP-14, FR-12. Prevents: an EU-residency migration becoming a domain-wide rewrite, given that first-party Anthropic has no eu inference_geo. Rule: domain code depends on a DraftingPort; Anthropic-direct, Bedrock-EU and Vertex-EU are interchangeable adapters selected by configuration.
- (decision) AD-11 No AGPL-licensed component in the deployed inference path without a held commercial licence. Binds CAP-9,12. Prevents: the detection model choice quietly making the whole product AGPL at commercialization. Rule: the deployed detector is Apache/BSD/MIT-licensed, or Ultralytics Enterprise is purchased before external release; the licence is recorded with the model version.
- (decision) AD-12 Training data is derived from the Validation event log, not written by a second path. Binds CAP-11,12, FR-14/22. Prevents: two writers of training records drifting, and dataset export missing corrections made on a surface that forgot to emit them. Rule: dataset export is a projection over Validation events; no code writes a training record directly.
- (decision) AD-13 Dependency direction: domain <- application <- adapters; the domain package imports no framework. Binds all. Prevents: PowerSync/Supabase/Flutter types leaking into the domain and making the sync engine unswappable. Rule: dependencies point inward only; the shared domain and the RapportDocument model are pure Dart with zero framework imports.
- (decision) AD-14 French domain vocabulary is the code vocabulary. Binds all. Prevents: one unit writing Disorder and another Desordre, then needing a translation layer nobody owns. Rule: the SPEC glossary terms appear verbatim (unaccented ASCII) as type and table names: mission, releve, zone, element_structurel, desordre, detection, validation, fiche_desordre, coupe, schema, rapport, ouvrage.
- (decision) AD-15 Authorization has one source of truth expressed twice, generated from one definition. Binds CAP-1,2,11, FR-2/24. Prevents: PowerSync sync rules and Postgres RLS disagreeing, so a device syncs rows the API would refuse. Rule: role/scope predicates are defined once and emitted to both sync rules and RLS policies; neither is hand-edited.
- (decision) AD-16 Data residency: all persistence and all first-party services run in an EU region from day one. Binds all. Prevents: an EU-hosting retrofit after real mission data exists, when RGPD stops being deferrable. Rule: Postgres, object storage, PowerSync service and the inference service are EU-hosted; the LLM path is the one documented exception and is tracked as an open question.
